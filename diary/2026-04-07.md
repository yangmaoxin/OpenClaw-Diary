### 1️⃣ Builder Pattern 设计

claw-code 使用经典的 Builder 模式构建系统提示词：

```rust
pub struct SystemPromptBuilder {
    output_style_name: Option<String>,      // 输出风格名称
    output_style_prompt: Option<String>,     // 输出风格描述
    os_name: Option<String>,                 // 操作系统
    os_version: Option<String>,              // 系统版本
    append_sections: Vec<String>,            // 追加区块
    project_context: Option<ProjectContext>, // 项目上下文
    config: Option<RuntimeConfig>,           // 运行时配置
}
```

**链式调用**：
```rust
SystemPromptBuilder::new()
    .with_output_style("Concise", "Prefer short answers.")
    .with_os("linux", "6.8")
    .with_project_context(project_context)
    .with_runtime_config(config)
    .render()
```

**优势**：可组合、可测试、职责清晰

### 2️⃣ Build 流程（区块顺序）

```
1. Intro Section（介绍）
2. Output Style Section（输出风格，可选）
3. System Section（系统级规则）
4. Doing Tasks Section（任务执行原则）
5. Actions Section（行动注意事项）
6. __SYSTEM_PROMPT_DYNAMIC_BOUNDARY__（动态边界标记）
7. Environment Section（环境上下文）
8. Project Context（项目上下文）
9. Instruction Files（CLAUDE.md 等指令文件）
10. Config Section（运行时配置）
11. Append Sections（追加区块）
```

**关键创新**：使用 `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` 分离静态指令和动态上下文

---

### 3️⃣ 动态边界分离（Dynamic Boundary Separation）

```rust
pub const SYSTEM_PROMPT_DYNAMIC_BOUNDARY: &str = "__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__";
```

**设计思想**：
- 静态内容（系统指令）可以被缓存
- 动态内容（git status、当前日期、上下文）每次不同
- 边界标记便于追踪和管理

**对比我的实现**：
- 我的 SOUL.md、AGENTS.md 没有区分静态/动态
- 所有内容混合在一起，无缓存优化空间

### 4️⃣ 项目上下文自动发现

```rust
pub struct ProjectContext {
    cwd: PathBuf,
    current_date: String,
    git_status: Option<String>,      // 自动获取 git status
    git_diff: Option<String>,        // 自动获取 git diff
    instruction_files: Vec<ContextFile>,
}
```

**发现机制**：
```rust
// 自动执行
git --no-optional-locks status --short --branch
git diff --cached
git diff
```

**对比我的实现**：
- 我没有自动获取 git status/diff
- 毛球大人的 USER.md 需要手动维护

### 5️⃣ 指令文件自动发现（祖先链追溯）

从当前目录向上查找：

| 文件路径 | 说明 |
|---------|------|
| `CLAUDE.md` | 主指令文件 |
| `CLAUDE.local.md` | 本地覆盖指令 |
| `.claw/CLAUDE.md` | .claw 目录下的指令 |
| `.claw/instructions.md` | .claw 目录下的指令 |

**去重机制**：基于内容哈希，相同内容只保留一份

**对比我的实现**：
- 我没有自动发现机制
- 所有指令都在固定位置的文件里

## 📝 今日结论

> **1. Builder Pattern** — 可组合、可测试的提示词构建方式
