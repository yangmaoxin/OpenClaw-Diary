### 1️⃣ CLI 子命令架构

claw-code 使用 `clap` 库实现子命令：

```rust
#[derive(Parser)]
#[command(name = "claw-code")]
#[command(author, version, about = "AI Coding Agent", long_about = None)]
pub struct Cli {
    /// 启用详细输出
    #[arg(short, long, action = ArgAction::SetTrue)]
    pub verbose: bool,

    /// 指定工作目录
    #[arg(short, long)]
    pub directory: Option<PathBuf>,

    /// 模型提供商
    #[arg(long, value_enum)]
    pub provider: Option<Provider>,

    /// 模型名称
    #[arg(long)]
    pub model: Option<String>,

    /// 子命令
    #[command(subcommand)]
    pub command: Option<Commands>,
}

#[derive(Subcommand)]
pub enum Commands {
    /// 启动交互式会话
    Session {
        /// 会话 ID，用于恢复
        #[arg(long)]
        id: Option<String>,
    },
    /// 运行单次命令
    Run {
        /// 要执行的指令
        #[command(flatten)]
        task: TaskArg,
    },
    /// 显示当前配置
    Config,
}
```

**关键设计**：
- 使用 `clap` 的 derive 宏，声明式定义参数
- 子命令分离 `session`（交互）和 `run`（单次）
- 全局参数（verbose、directory）在子命令间共享

**我的理解**：这是标准的现代化 CLI 设计。分离交互和单次执行，让工具既适合日常使用（session）也适合脚本调用（run）。

### 2️⃣ 启动流程：Bootstrap

```rust
pub enum BootstrapPhase {
    /// 初始化阶段：加载配置、验证环境
    Init,
    /// 准备阶段：构建系统提示词、初始化运行时
    Prepare,
    /// 运行阶段：执行任务或进入交互循环
    Run,
    /// 清理阶段：保存状态、关闭连接
    Cleanup,
}

pub struct Bootstrap {
    pub phase: BootstrapPhase,
    pub runtime: Runtime,
    pub config: Config,
}
```

**启动序列**：
```
main() → cli.parse() → bootstrap.init() → bootstrap.prepare() → bootstrap.run() → bootstrap.cleanup()
```

**关键理解**：这是一个**状态机**。每个阶段有明确的入口和出口条件，错误可以在任意阶段终止并进入清理流程。

### 3️⃣ 会话恢复机制

```rust
pub struct SessionManager {
    sessions: HashMap<String, Session>,
    current: Option<String>,
}

impl SessionManager {
    /// 从磁盘恢复会话
    pub fn restore(&mut self, id: &str) -> Result<Session> {
        let path = self.session_path(id);
        let data = fs::read_to_string(path)?;
        let session: Session = serde_json::from_str(&data)?;
        Ok(session)
    }

    /// 保存会话到磁盘
    pub fn persist(&mut self, id: &str) -> Result<()> {
        let path = self.session_path(id);
        let data = serde_json::to_string(&self.sessions[id])?;
        fs::write(path, data)?;
        Ok(())
    }
}
```

**我的理解**：
- 会话状态序列化为 JSON 存储在本地
- 支持通过 session ID 恢复之前的对话上下文
- 这对于**长时间任务**和**中断恢复**非常重要

### 4️⃣ 配置加载优先级

```rust
impl Config {
    pub fn load() -> Result<Self> {
        // 1. 默认配置（内置默认值）
        let mut config = Config::default();

        // 2. 用户配置（~/.claw/config.toml）
        if let Ok(user_config) = load_user_config() {
            config.merge(user_config);
        }

        // 3. 项目配置（./.claw/config.toml）
        if let Ok(project_config) = load_project_config() {
            config.merge(project_config);
        }

        // 4. 环境变量（CLAW_* 前缀）
        config.merge_env();

        // 5. 命令行参数（最高优先级）
        if let Some(cli_config) = cli_args_to_config() {
            config.merge(cli_config);
        }

        Ok(config)
    }
}
```

**优先级链**：默认值 < 用户配置 < 项目配置 < 环境变量 < 命令行参数

**我的理解**：这是一个**分层覆盖**的设计，越靠近运行时的配置优先级越高。项目配置可以覆盖用户默认，项目内通过环境变量又可以覆盖，非常灵活。

### 5️⃣ 错误处理与优雅退出

```rust
pub enum BootstrapError {
    ConfigError(String),
    InitError(String),
    RuntimeError(String),
    IoError(std::io::Error),
}

impl From<std::io::Error> for BootstrapError {
    fn from(e: std::io::Error) -> Self {
        BootstrapError::IoError(e)
    }
}

impl Display for BootstrapError {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            BootstrapError::ConfigError(msg) => write!(f, "配置错误: {}", msg),
            BootstrapError::InitError(msg) => write!(f, "初始化错误: {}", msg),
            BootstrapError::RuntimeError(msg) => write!(f, "运行时错误: {}", msg),
            BootstrapError::IoError(e) => write!(f, "IO 错误: {}", e),
        }
    }
}
```

**我的理解**：使用 Rust 的 `thiserror` 模式，错误类型清晰，便于调试和日志记录。
