### 1️⃣ Builder 模式：SystemPromptBuilder

claw-code 使用**完全程序化的 Builder 模式**构建系统提示词：

```rust
SystemPromptBuilder::new()
    .with_output_style(name, prompt)
    .with_os(os_name, os_version)
    .with_project_context(project_context)
    .with_runtime_config(config)
    .build()  // → Vec<String> 多个分块
```

**关键设计**：
- `build()` 返回 `Vec<String>`（多个字符串分块），而非单个大字符串
- 每个分块是一个独立的"章节"（section）
- 最终由 `render()` 合并成完整提示词

**我的理解**：这是工程化程度非常高的设计。分块的好处是：
1. 可以在运行时**动态替换**某个 section（比如切换 output_style）
2. 便于**单元测试**每个 section 的输出
3. **组合自由**，想加什么就 `.append_section()`

### 2️⃣ 静态/动态边界：SYSTEM_PROMPT_DYNAMIC_BOUNDARY

```rust
pub const SYSTEM_PROMPT_DYNAMIC_BOUNDARY: &str = "__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__";
```

在 `build()` 输出中，这个标记**将提示词分为两大区**：

```
[静态区 - 固定不变]
- 介绍语（Intro）
- 输出风格（Output Style）
- 系统规则（System）
- 任务行为准则（Doing Tasks）
- 行动谨慎指南（Actions with Care）

__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__   ← 边界标记

[动态区 - 每次请求更新]
- 环境上下文（Environment context）
- 项目上下文（Project context，含 git status/diff）
- 指令文件（CLAUDE.md 等）
- 运行时配置（Runtime config）
```

**我的理解**：
- 静态区包含基础规则和行为约束，**不频繁变化**
- 动态区包含**每次都重新计算的上下文**（cwd、日期、git 状态、instruction files）
- 这个边界标记让模型知道哪些是稳定的系统承诺，哪些是环境快照

### 3️⃣ 项目上下文发现：目录链追溯 + 去重

```rust
fn discover_instruction_files(cwd: &Path) -> Vec<ContextFile> {
    // 从当前目录向上遍历到根，构建目录链
    // 每个目录检查 4 个位置：
    //   1. {dir}/CLAUDE.md
    //   2. {dir}/CLAUDE.local.md
    //   3. {dir}/.claw/CLAUDE.md
    //   4. {dir}/.claw/instructions.md
    // 去重：相同内容只保留一次（stable_content_hash）
}
```

**设计亮点**：
- **向上追溯**：子目录自动继承父目录的指令，无需重复声明
- **去重机制**：相同内容（规范化后比较 hash）只保留最内层的
- **范围标注**：每个文件标注 scope（如 `scope: /tmp/project`）

### 4️⃣ Git 状态快照

```rust
pub struct ProjectContext {
    pub cwd: PathBuf,
    pub current_date: String,
    pub git_status: Option<String>,   // ← 自动发现
    pub git_diff: Option<String>,     // ← 自动发现
    pub instruction_files: Vec<ContextFile>,
}
```

在 `discover_with_git()` 时自动获取：
- `git status --short --branch` → git_status
- `git diff --cached`（ staged）和 `git diff`（ unstaged）→ git_diff

**我的理解**：这是一个**极其实用**的设计。模型可以直接看到当前未提交的改动，无需用户手动描述"我改了啥"。

### 5️⃣ 指令文件预算控制

```rust
const MAX_INSTRUCTION_FILE_CHARS: usize = 4_000;    // 单文件上限
const MAX_TOTAL_INSTRUCTION_CHARS: usize = 12_000;  // 全局总上限
```

超过则截断并标记 `[truncated]`。

**我的理解**：这是一个**非常成熟**的工程决策。防止长指令文件塞满 context window，给模型留出推理空间。

### 6️⃣ 提示词结构拆解

完整的提示词 sections 顺序：

```
1. 介绍语（Intro）              — 角色定义，基础行为承诺
2. 输出风格（Output Style）       — 可选，自定义响应风格
3. 系统规则（System）            — 显示方式、工具执行、提示注入识别
4. 任务行为（Doing Tasks）        — 修改前阅读、保持小改动、安全报告
5. 行动谨慎（Actions with Care）  — 高风险操作需用户明确授权
6. ──────────── 边界 ────────────
7. 环境上下文（Environment）      — 模型名、cwd、日期、平台
8. 项目上下文（Project Context）  — git status/diff
9. 指令文件（Instructions）       — CLAUDE.md 等文件内容
10. 运行时配置（Runtime Config）  — permission mode 等
```

### 7️⃣ 权限模式分层

```rust
pub enum PermissionMode {
    ReadOnly,
    WorkspaceWrite,
    DangerFullAccess,
    Prompt,
    Allow,
}
```

系统提示词中内嵌：
> "Carefully consider reversibility and blast radius. Local, reversible actions like editing files or running tests are usually fine. Actions that affect shared systems, publish state, delete data, or otherwise have high blast radius should be explicitly authorized by the user or durable workspace instructions."

## 📝 今日结论

claw-code 的 System Prompt 架构最值得学习的三个设计：

> **1. 静态/动态边界** — 让模型知道什么是"永恒的规则"，什么是"此刻的快照"
